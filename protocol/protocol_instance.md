# DM-MC 上位机通信协议
# 这里的通讯协议只是一个示例

## 1. 通信方向与传输方式

本协议用于上位机通过 USB CDC 虚拟串口向 DM-MC 下位机发送数据信息。

- 每帧固定为 20 字节。
- 多字节数值使用小端字节序。
- `float32` 使用 IEEE 754 单精度格式。
- 上位机必须发送原始二进制字节，不能发送十六进制字符串。
- USB CDC 数据可以分段到达，也可以一次到达多帧，下位机解析器会按字节流组帧。

## 2. 帧格式

| 字节偏移 | 长度 | 字段 | 编码 | 说明                       |
| ---: | ---: | --- | --- |----------------------------|
| 0 | 1 | 帧头 1 | `uint8` | 固定为 `0xAA`              |
| 1 | 1 | 帧头 2 | `uint8` | 固定为 `0x55`              |
| 2 | 4 | `x` | `float32` 小端 | 世界坐标 x，单位 mm        |
| 6 | 4 | `y` | `float32` 小端 | 世界坐标 y，单位 mm        |
| 10 | 4 | `z` | `float32` 小端 | 世界坐标 z，单位 mm        |
| 14 | 2 | `phi_raw` | `int16` 小端 | 末端姿态角的 10 倍整数值   |
| 16 | 1 | `action` | `uint8` | 动作码                     |
| 17 | 1 | `checksum` | `uint8` | 字节 2～16 的累加和低 8 位 |
| 18 | 1 | 帧尾 1 | `uint8` | 固定为 `0x0D`              |
| 19 | 1 | 帧尾 2 | `uint8` | 固定为 `0x0A`              |

### 2.1 姿态角编码

上位机发送前将角度乘以 10，然后转换为有符号 16 位整数：

```text
phi_raw = round(phi_degree * 10)
```

下位机接收后使用：

```text
phi_degree = phi_raw / 10.0
```

例如 `phi = 75.0°` 时，`phi_raw = 750 = 0x02EE`，小端字节顺序为 `EE 02`。

`phi` 表示末端姿态角

### 2.2 动作码

| `action` | 动作       |
| ---: |------------|
| `0` | 不改变状态 |
| `1` | 动作1      |
| `2` | 动作2      |
| `3` | 动作3      |

## 3. 校验和算法

`checksum` 是字节偏移 2～16（共 15 字节）的无符号累加和，只保留低 8 位：

```text
checksum = (byte[2] + byte[3] + ... + byte[16]) & 0xFF
```

帧头、校验和或帧尾不正确时，下位机不会更新目标位姿和动作。

## 4. 完整示例

上位机需要发送如下命令：

```text
x      = 160.0 mm
y      = 0.0 mm
z      = 180.0 mm
phi    = 75.0°
action = 1
```

各字段的线上字节为：

| 字段 | 字节 |
| --- | --- |
| 帧头 | `AA 55` |
| `x = 160.0` | `00 00 20 43` |
| `y = 0.0` | `00 00 00 00` |
| `z = 180.0` | `00 00 34 43` |
| `phi_raw = 750` | `EE 02` |
| `action = 1` | `01` |
| `checksum` | `CB` |
| 帧尾 | `0D 0A` |

完整 20 字节帧为：

```text
AA 55 00 00 20 43 00 00 00 00 00 00 34 43 EE 02 01 CB 0D 0A
```

### 4.1 逐字节解释

| 偏移 | 字节 | 字段 | 含义                                                                           |
| ---: | ---: | --- |--------------------------------------------------------------------------------|
| 0 | `AA` | 帧头 | 第一个固定帧头字节 `0xAA`                                                      |
| 1 | `55` | 帧头 | 第二个固定帧头字节 `0x55`                                                      |
| 2 | `00` | `x` | `x` 的第 1 字节（最低有效字节）                                                |
| 3 | `00` | `x` | `x` 的第 2 字节                                                                |
| 4 | `20` | `x` | `x` 的第 3 字节                                                                |
| 5 | `43` | `x` | `x` 的第 4 字节（最高有效字节）；`00 00 20 43` 按小端 `float32` 解码为 `160.0` |
| 6 | `00` | `y` | `y` 的第 1 字节（最低有效字节）                                                |
| 7 | `00` | `y` | `y` 的第 2 字节                                                                |
| 8 | `00` | `y` | `y` 的第 3 字节                                                                |
| 9 | `00` | `y` | `y` 的第 4 字节（最高有效字节）；`00 00 00 00` 按小端 `float32` 解码为 `0.0`   |
| 10 | `00` | `z` | `z` 的第 1 字节（最低有效字节）                                                |
| 11 | `00` | `z` | `z` 的第 2 字节                                                                |
| 12 | `34` | `z` | `z` 的第 3 字节                                                                |
| 13 | `43` | `z` | `z` 的第 4 字节（最高有效字节）；`00 00 34 43` 按小端 `float32` 解码为 `180.0` |
| 14 | `EE` | `phi_raw` | 姿态角整数值的低字节                                                           |
| 15 | `02` | `phi_raw` | 姿态角整数值的高字节；小端整数为 `0x02EE = 750`，所以 `phi = 750 / 10 = 75.0°` |
| 16 | `01` | `action` | 动作码 `1`                                                                     |
| 17 | `CB` | `checksum` | 字节 2～16 累加和的低 8 位                                                     |
| 18 | `0D` | 帧尾 | 第一个固定帧尾字节，即 `\r`                                                    |
| 19 | `0A` | 帧尾 | 第二个固定帧尾字节，即 `\n`                                                    |

本帧的校验和计算为：

```text
(00 + 00 + 20 + 43 + 00 + 00 + 00 + 00 +
 00 + 00 + 34 + 43 + EE + 02 + 01) & FF
= 1CB & FF
= CB
```

其中所有加数都是十六进制字节值。

这是二进制数据的十六进制展示。上位机应实际写入下列 20 个原始字节：

```text
0xAA, 0x55, 0x00, 0x00, 0x20, 0x43, 0x00, 0x00, 0x00, 0x00,
0x00, 0x00, 0x34, 0x43, 0xEE, 0x02, 0x01, 0xCB, 0x0D, 0x0A
```

## 5. Python 组帧示例

```python
import struct


def build_frame(x: float, y: float, z: float,
                phi_degree: float, action: int) -> bytes:
    phi_raw = round(phi_degree * 10.0)

    if not -32768 <= phi_raw <= 32767:
        raise ValueError("phi is outside int16 range")
    if not 0 <= action <= 255:
        raise ValueError("action is outside uint8 range")

    payload = struct.pack("<fffhB", x, y, z, phi_raw, action)
    checksum = sum(payload) & 0xFF

    return b"\xAA\x55" + payload + bytes([checksum]) + b"\x0D\x0A"


frame = build_frame(160.0, 0.0, 180.0, 75.0, 1)
serial_port.write(frame)
```

`struct.pack("<fffhB", ...)` 中：

- `<` 表示小端字节序。
- `fff` 表示 3 个 IEEE 754 `float32`。
- `h` 表示 1 个 `int16`。
- `B` 表示 1 个 `uint8`。
